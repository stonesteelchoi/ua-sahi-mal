At the user's request, `scripts/psa_structure_audit.py` statically inspected the
entire deduplicated train/validation population. It read source files as bytes;
it did not execute, import, or dynamically load PE files. Test payloads were
not accessed. This is a diagnostic census, **not** an independent-crosscheck
pass or authorization to freeze the protocol.

| Result | Files |

The 114 errors comprise 41 source-size mismatches and 10 source-SHA-256
mismatches already identified by the full source-integrity audit, plus 62
`PeFormatError` cases where data directories exceed the declared optional
header and one case with a missing or truncated declared optional header.
Thus 168,969 selected files match their expected source size and SHA-256;
168,896 of those (99.9568%) have agreeing comparison fields. This percentage
is descriptive and is not a predefined pass threshold.

All 10 disagreements include `section_count`; five also include
`raw_section_overlay_boundary`. Their sample IDs are 12755, 14533, 23434,
25449, 39310, 39778, 59951, 64388, 82126, and 97450. The ledger records
pefile warnings about null, truncated, or implausible sections in these cases.
This is consistent with different malformed-PE parsing policies, but does not
by itself establish which parser's region assignment is correct.

The pefile-native overlay start differs from the PeAtlas section-end boundary
in 1,854 parsed files. This native-overlay diagnostic is separate from the
normalized raw-section boundary comparison above. It needs semantic review
before either definition is used as an authoritative overlay label.
