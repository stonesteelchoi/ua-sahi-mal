## 4. 라벨 품질 — 임계 규칙을 명시해야 함

`list` 열(Whitelist/Blacklist)은 AV 탐지수와 **깨끗하게 일치하지 않는다**.

| 사례 | 수 | 비고 |
|---|---|---|
| 정상인데 `positives > 0` | **1,771** (정상의 2.04%) | 1회 탐지 1,470건(오탐으로 볼 만함)이나 꼬리가 최대 **34**까지 간다 |
| 악성인데 `positives = 0` | **105** | AV 합의가 전혀 없음 |
| 악성인데 `positives ≤ 5` | 296 | |
| 정상인데 `total = 0` | 존재 | 스캔 엔진 수 0 → `positives=0`이 무의미 |

`positives` 분포: 정상 중앙값 0 / 최대 34, 악성 중앙값 44 / 최대 70.

→ **P0 결정 필요**: eligibility 규칙에 라벨 임계를 명시한다. 예) 정상은 `total ≥ 40 AND positives = 0`, 악성은 `positives ≥ 10`. 경계 구간은 주 분석에서 제외하고 그 수를 보고한다. 임계를 정하지 않으면 라벨 잡음이 H1/H2 효과와 뒤섞인다.

## 5. 출처 불일치(shortcut) 증거 — **가장 중요한 발견**

메타데이터만으로 악성 여부를 얼마나 맞힐 수 있는지 AUROC로 측정했다(악성 = positive).

| 변수 | AUROC | 바이트에서 유도 가능? | 해석 |
|---|---|---|---|
| `submitted` | 0.2215 (**대칭 0.7785**) | 아니오 | 정상은 **거의 전부 2018-06-24 하루에 일괄 등록**(범위 2018-06-24~08-26), 악성은 2018-02-15~2020-10-26(중앙값 2018-03-26) |
| `total`(스캔 엔진 수) | 0.3053 (**대칭 0.6947**) | 아니오 | 정상이 더 많은 엔진에 스캔됨(중앙값 66 vs 56) |
| `entropy` | **0.7576** | **예** | 악성이 더 높음(중앙값 6.920 vs 6.129) — 패킹 |
| `length` | **0.6551** | **예** | 악성이 더 큼(중앙값 323,720 vs 135,984) |

`submitted`·`total`은 파일 바이트에 없으므로 모델에 직접 새지는 않는다. 그러나 **정상과 악성이 서로 다른 채널로 들어왔다는 증거**다(정상=하루치 일괄 수집, 악성=2년 반에 걸친 수집). 채널이 다르면 컴파일러·링커 버전, 코드 서명 유무, 패커 사용률 같은 **바이트 수준 상관물**이 생긴다.

단변량으로는 모두 프로토콜 §5의 0.90 게이트 아래다. 그러나 §5가 요구하는 결합 모델에는 header/overlay/**certificate 크기**와 **signed** 플래그가 들어가며, 정상이 Windows·상용 설치본 중심이라 **`signed`가 가장 강한 단일 변수가 될 가능성이 높다.** 2단계 감사에서 이것부터 측정한다.

## 6. 입력 표현에 걸리는 문제 — `interval-binned-v1` 정책이 라벨과 상관됨

`interval-binned-v1`은 파일 크기가 P = 50,176(224×224) 미만이면 `nearest_byte_repetition`, 이상이면 `contiguous_interval_mean_pool`을 쓴다.

| | < 50,176 B (nearest-repetition) | 비율 |
|---|---|---|
| 정상 86,812 | **25,338** | **29.2%** |
| 악성 114,737 | **9,415** | **8.2%** |

**정상이 악성보다 3.5배 자주 nearest-repetition 경로를 탄다.** 두 정책은 래스터의 질감이 눈에 띄게 다르므로(반복 확대 vs 평균 풀링), 모델이 내용이 아니라 **변환 정책 자체를 학습할 수 있다.**

→ **P0 결정 필요**: ① `policy`를 manifest 필드로 남기고 분할 층화 변수에 추가, ② 정책별 subgroup 결과를 별도 보고, ③ 민감도 분석으로 mean-pool 경로만으로 H1/H2를 재검정. 이 셋을 동결 전에 프로토콜에 반영한다.

크기 분포(참고): 정상 min 1,024 / p25 40,330 / 중앙값 135,984 / p75 428,616 / max 201,367,304. 악성 min 512 / p25 126,336 / 중앙값 323,720 / p75 742,949 / max 41,988,096.

## 8. `samples-augmented.csv` 분석 — **imphash 제공, G5 게이트 통과**

배포 페이지에 없던 이 파일은 `samples.csv`와 동일한 201,549행에 **`imphash` 열 하나가 추가**된 것이다
(id 집합 완전 일치, 다른 열은 동일). 이 한 열이 near-duplicate 그룹 문제를 바로 해결한다.

| 항목 | 값 |
|---|---|
| imphash 보유 | 190,550 (94.5%) → **66,470개 그룹** |
| imphash 없음(import table 부재) | 10,999 — **정상 9,840 / 악성 1,159** |
| 그룹 크기 | 최대 20,271, p99 = 19, 중앙값 1, 단독 그룹 53,451개 |
| 상위 10 그룹 점유율 | 25.1% |

### 8.1 그룹 분리 분할 성립 — **통과**

'import 없음' 표본을 개별 단위로 취급하면 분할 단위는 **77,469개**다. 그룹을 통째로 배정하는 무작위
70/15/15 시뮬레이션(seed 42) 결과:

| split | 표본 수 | 비율 |
|---|---|---|
| train | 141,329 | 70.1% |
| val | 30,243 | 15.0% |
| test | 29,977 | 14.9% |

DikeDataset이 5개 그룹으로 탈락한 것과 대조적으로, PSA는 **G5를 여유 있게 통과**한다.
다만 단일 최대 그룹(20,271 = 전체의 10.1%)이 한 split에 통째로 들어가므로, 층화 시 이 그룹을
train에 고정하고 나머지로 비율을 맞추는 규칙을 명시해야 한다.

### 8.2 새 shortcut 증거 — imphash가 클래스를 거의 완전히 가른다

| 그룹 순도 | 그룹 수 | 비고 |
|---|---|---|
| 정상만 | 36,760 | |
| 악성만 | 28,876 | |
| **혼합** | **834 (1.3%)** | 표본 기준 34,384개 = 18.0% |

**imphash 그룹의 98.7%가 클래스 순수**하다. 즉 import table만 보면 정상/악성이 거의 결정된다.
imphash는 바이트에서 유도되므로 CNN이 이를 학습하는 것은 정당한 신호이기도 하지만, 동시에
**모델이 "악성 의미"가 아니라 "import table 인식"을 하고 있을 가능성**을 뜻한다.
§5 감사에 `imphash` 파생 변수(그룹 크기, 그룹 다수 클래스)를 넣어 단독 AUROC를 반드시 측정한다.

상위 그룹 구성(발췌): `dae02f32…` n=20,271 악성 2.8%(최소 import 패턴, 대부분 정상),
`f34d5f2d…` n=5,992 악성 54.0%, 그 아래 `3786a4cf…`(5,788) `6d2bdf26…`(3,202) `c1280c32…`(2,975) 등은
**악성 100%** — 명확한 악성 패밀리 클러스터다.

### 8.3 예상과 반대였던 것

`imphash` 없음(=import table 부재)은 보통 패킹 신호라 악성에 몰릴 것으로 예상했으나,
실제로는 **정상 9,840 / 악성 1,159로 정상에 몰려 있다**(정상의 11.3% vs 악성의 1.0%).
.NET 어셈블리·소형 유틸리티·드라이버 등이 원인으로 추정되나 미확인이다.
이 역시 클래스와 상관된 변수이므로 §5 감사에 포함한다.

## 9. 도구 — `scripts/psa_stream_audit.py`

아카이브가 solid 7z라 단일 파일 임의 접근이 비싸다. 이 스크립트는 **한 번의 순차 스트리밍**으로
표본마다 sha256·MZ 판정·PE32/PE32+·machine·timestamp·subsystem·linker 버전·section 수와 이름·
실행/비실행 섹션 바이트·overlay·certificate·signed·최대 섹션 엔트로피·비표준 섹션 수·imphash·
파일 엔트로피·`interval-binned-v1` 정책을 계산해 manifest CSV로 쓴다.

**표본 바이트는 메모리에서만 다루고 디스크에 쓰지 않는다.** 따라서 해제가 필요 없고,
실시간 백신 검사가 발동하지 않으며 제외 설정도 필요 없다. 실행·임포트·동적 로딩은 하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts\psa_stream_audit.py `
  --archive "C:\research\ua-sahi-mal\datasets\pe-machine-learning-dataset.7z" `
  --out "D:\secure-malware-data\psa\manifest_stage2.csv" --limit 400   # 먼저 smoke
```

`--limit`을 빼면 전량(117.7 GiB 압축 해제 상당)을 처리한다. 필요 패키지: `py7zr`, `pefile`.
