## 2. 지금까지 한 일

### 2.1 데이터 (KISA → PSA)
- **KISA 판정:** 2017/2018/2019 원본·챌린지 데이터셋은 오프라인 방문 전용, 원본 반출 불가.
  C-TAS 온라인 738건은 추출 특징 json뿐이고 **정상 표본이 아예 없어** 이진 탐지 구성 불가.
- **대체 탐색:** Kaggle(특징표), DikeDataset(982/8,970, 5패밀리·figshare 재포장) 모두 부적합 판정.
  PSA만이 원본 바이트 + 정상·악성 양쪽 + 충분한 규모를 만족.
- **PSA 확보·검증:** 43.8 GB 7z, SHA-256 `a8b02407…ef51215e` 공식값 일치, 해제 117.7 GiB.
  다운로드가 두 번 중단(97%)됐다가 세 번째에 완결.

### 2.2 P0 게이트 (전부 실측)
- 표본↔라벨 **결합률 100.0000%** (201,549 = 201,549, 불일치 0).
- 전수 PE 파싱 11.1분(180 MiB/s), **파싱 실패 48개 = 0.024%**.
- eligible **199,316** (정상 84,928 / 악성 114,388). 라벨 규칙: 정상 `total≥40∧positives=0`,
  악성 `positives≥10`, 경계 2,184 제외.
- 분할: imphash 그룹 분리(77,469 단위) + label×pe_kind×repr_policy 층화.
  `split_sha256 843bcb80…099b`, train 139,192 / val 29,953 / test 30,171.
- 래스터 199,316개 materialise(3.1분, 658 MiB/s, 37.3 GiB). 왕복 검사 2,000개 실패 0.
  래스터 중복 116그룹 — **split·라벨 경계 넘는 것 0** (누수·라벨잡음 없음).

### 2.3 데이터 편향 감사 (§5) — 핵심 발견
- 메타데이터(바이트 유도 20변수)만으로 **그룹 분리 5-fold AUROC 0.95** → §5 게이트 걸림.
- ablation: 어느 변수군을 빼도 0.90 아래로 안 떨어짐 = **중복 교란**. 정체는 **15년 툴체인 격차**
  (정상 VS2005~2013, 악성 VC6·Delphi).
- **연대 변수만 매칭**(linker/timestamp)해 제거하면 0.90~0.91로 유지 — 남는 분리력은
  패킹 엔트로피(0.86)·서브시스템(GUI vs 콘솔) 등 **실제 정적 악성 특성**.
- 결론: 편향의 일부는 수집 아티팩트(제거 가능), 일부는 진짜 특성. **metadata 0.95를 필수 기준선**으로
  보고하고, CNN이 그 위로 얼마나 올라가는지가 논의 대상.

### 2.4 검증 가능한 예측
PE 헤더는 래스터 좌상단 소수 픽셀. 위 해석이 맞다면 Grad-CAM은 헤더가 아니라
**고엔트로피 실행 섹션**에 몰려야 한다 → §11 구조별 CAM mass로 직접 판정.

## 5. 사용량 점검 — 어디까지 갈 수 있나

### 5.1 최근 구간 소비 내역 (마지막 압축 이후, 234턴 · 약 8시간)

가중 실효 토큰 기준 (캐시 읽기 0.1×, 캐시 쓰기 2×, 출력 5×):

```
 84.0%  ██████████████████████████████████  명령·도구목록·대화맥락 (매 턴 다시 읽음)
  8.5%  ███                                  추론과 답변 작성
  4.7%  ██                                   사용자 컴퓨터 작업 (장비 브리지)
  1.5%  █                                    파일·셸 작업
  0.9%  █                                    프로젝트 기록·파일 전달·질문
  0.5%  █                                    웹 조사
```

### 5.2 해석 (쉬운 말로)
- **비용의 84%는 실제 작업이 아니라 "매 턴 배경 다시 읽기"** 다. 시스템 지시문 + 방대한 도구 목록 +
  매 턴 주입되는 스킬 목록 + 길어진 대화 기록을 턴마다 다시 훑는 고정비다.
- **진짜 연구 작업(장비·파일·웹)은 다 합쳐 16%뿐.** 무거운 계산은 사용자 PC에서 돌고 짧은 로그만
  돌아오므로 내 쪽 비용이 작다.
- 즉 남은 예산은 **"얼마나 무거운 계산을 하느냐"가 아니라 "몇 번 주고받느냐"** 로 정해진다.
  턴당 고정비가 크다.

### 5.3 남은 예산 판단
- 현재 남은 실효 예산 ≈ **1,500만 토큰**. 실측 턴당 평균 ≈ 5.5만~6만 → **대략 250~280턴** 여유.
- 남은 계획 전체(pilot → 3-seed 학습 → Grad-CAM → perturbation → 통계 → 구조분석 → P2 →
  1차 결과 초안)에 내가 개입하는 왕복은 **약 60~120턴**으로 추정.
- **판단: 예산은 넉넉하다.** 학습·XAI·통계까지 끝내고 결과 초안까지 무리 없이 도달 가능.
  예산이 병목이 될 상황은 하나뿐 — 큰 로그·파일을 반복해서 붙여넣으며 디버깅 루프를 오래 도는 경우.

### 5.4 예산 아끼는 법 (권장)
1. **작업을 큰 턴으로 묶기** — 턴당 고정비가 크므로, 잘게 쪼갠 왕복보다 한 번에 여러 단계를 묶는 게 효율적.
2. **긴 출력은 요약해서** — 전체 로그 대신 마지막 요약 줄(예: `done: … MiB/s`)만 붙여넣기.
3. **무거운 계산은 계속 장비에서** — 지금 방식 그대로. 클라우드로 올리지 않기.
4. 큰 파일 재열람 피하기(이미 읽은 manifest 등).
