설계는 `docs/RESEARCH_PLAN_v2.md`에 있다. 이 문서는 **그것을 어떻게 돌리는가**만 다룬다.

## 0. 무엇을 측정하는가

한 문장으로: **분류기가 계열을 맞히기 위해 실제로 필요로 하는 바이트 구간을 찾고, 그 구간이 찾는 데 쓰이지 않은 다른 모델에서도 필요한지 확인한다.**

측정은 전부 마스킹 후 재추론이다. 사람 주석은 어디에도 쓰이지 않는다.

| 단계 | 답하는 것 | 판정 |
|---|---|---|
| 합성 통제 | 심어놓은 답을 되찾는가 | D1 |
| 전수 오클루전 | 근거 질량의 기준선 | (D5의 분모) |
| 예산 라우팅 | 전수 탐색을 얼마나 회수하는가 | D5, D6 |
| 교차 검증 | 다른 모델·다른 표현에서도 필요한가 | D2, D3, D4 |

## 1. 코퍼스 구축

`train.7z`는 압축 18.8 GB, 해제 198 GB다. 전부 풀 필요는 없다.

- `.bytes`는 **solid folder 69–93에만** 있다. `.asm` 144 GB는 건너뛴다 — 바이트 구간을 가리는 데 디스어셈블리는 필요 없다.
- folder 하나씩 스크래치에 풀고, 선택된 검체만 PNG로 변환하고, 푼 것은 지운다. 추가 점유는 코퍼스 전체가 아니라 **folder 하나**다.
- 중단해도 이어서 돌릴 수 있다(`--state`). 한 번 호출의 실행 시간이 전체 추출 시간보다 훨씬 짧으므로 이 성질이 필요하다.

```bash
python scripts/big2015_prepare_corpus.py \
  --archive  datasets/train.7z \
  --labels   datasets/big2015/trainLabels.csv \
  --rasters  datasets/big2015/rasters \
  --scratch  /tmp/scratch \
  --state    datasets/big2015/prepare_state.json \
  --per-family 200 \
  --max-folders 2 \
  --manifest datasets/big2015/manifest.json     # 전 folder 완료 시에만 기록
```

folder가 남아 있는 동안 같은 명령을 반복하면 된다.

**실측 (2026-09-03)**: 계열당 200 상한 → 1,642 선택 → **1,636 변환**(6건은 64 KB 미만이거나 파싱 실패), 래스터 854 MB, 25 folder 총 약 25분.

| 계열 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 검체 | 200 | 197 | 200 | 198 | **42** | 199 | 200 | 200 | 200 |

계열 4는 전체가 42개다. 상한을 채우지 못한 것이 아니라 **그게 전부**이며, 층화의 목적이 바로 이 계열을 살리는 데 있다.

### 분할

`train / validation / test = 70 / 15 / 15`. 분할 키는 **파일 이름이 아니라 내용 해시**다. 같은 바이트가 다른 이름으로 두 번 들어와도 같은 쪽에 떨어진다.

## 2. 분류기 학습

```bash
python -m ua_sahi_mal.evidence train \
  --manifest data/big2015/manifest.json \
  --rasters  data/big2015/rasters \
  --out      runs/evidence/models \
  --classes 9 --epochs 10
```

| 모델 | 표현 | 역할 | torch |
|---|---|---|---|
| A `tiled` | 512×512 바이트 타일 (원해상도) | **탐색** | 필요 |
| B `thumbnail` | 256×256 전체 이미지 | **주 지표** (교차 모델) | 필요 |
| C_text | 히스토그램 + 해시 bigram | 교차 표현 (이미지를 안 봄) | 불필요 |

A와 B는 **구조·seed·표현이 모두 다르다.** 같은 몸통을 공유하면 §2의 교차 모델 논증이 통째로 무너지므로, 이는 편의가 아니라 요건이다.

A가 타일 기반인 이유는 두 가지다. 4 KB 오클루전이 타일 하나만 바꾸므로 **재추론이 타일 한 장의 순전파**로 끝나고(전수 탐색이 가능해지는 이유), 첫 conv의 stride가 4라 8행짜리 마스킹이 첫 특징맵에서 두 칸을 차지한다 — 신호가 평균으로 씻겨나가기 전에 네트워크가 본다.

증강은 쓰지 않는다. 수평 flip은 바이트 순서를 뒤집고, 회전과 mosaic은 좌표계를 파괴한다.

## 3. 합성 통제 집합 (D1)

```bash
python -m ua_sahi_mal.evidence synth \
  --manifest data/big2015/manifest.json \
  --rasters  data/big2015/rasters \
  --out      runs/evidence/synthetic \
  --pairs 24 --blocks 4
```

- **양성**: host(계열 X)에 **다른 계열 Y**의 구간을 알려진 오프셋에 이식. 계열 Y의 근거를 물으면 그 구간이 나와야 한다.
- **하드 네거티브**: 같은 host, 같은 오프셋, 같은 길이, 다만 이식 구간이 **host 자신의 계열**에서 왔다. 이음매는 같고 내용만 다르다.
- 이음매 엔트로피 차가 **0.3 bit**를 넘으면 donor를 거부한다(예외로 강제).
- 삽입이 아니라 **치환**이다. 양성과 네거티브의 길이가 정확히 같아야 검출기가 길이로 가르지 못한다.

거부된 host는 매니페스트에 **이유와 함께 기록**된다. 조용히 걸러진 통제 집합은 편향된 통제 집합이다.

### 안전

전 과정이 BIG2015 `.bytes`(배포 시점에 PE 헤더가 제거되어 실행 불가)에서 온 바이트 배열 위에서만 일어난다. 헤더 합성도, 재배치 수정도, entry point도 없다 — **실행 가능한 산출물이 원천적으로 생기지 않는다.** 출력은 PNG와 NPZ뿐이다.

## 4. 프로토콜 실행

```bash
python -m ua_sahi_mal.evidence run \
  --manifest  data/big2015/manifest.json \
  --rasters   data/big2015/rasters \
  --models    runs/evidence/models \
  --synthetic runs/evidence/synthetic \
  --out       runs/evidence/results \
  --per-family 5 --fill-robustness
```

`--fill-robustness`는 전수 탐색을 채움값 3종으로 반복한다(D4). 비용이 3배이므로 기본은 꺼져 있다.

산출물 `evidence_results.json`에는 **요약만이 아니라 검체별 원자료**가 들어간다. 판정표를 탐색을 다시 돌리지 않고 재계산할 수 있어야 하기 때문이다.

## 5. 판정표

임계는 `src/ua_sahi_mal/evidence/criteria.py` 한 곳에 있고, 판정은 기록이 아니라 **계산**이다.

| # | 조건 | 미달 시 |
|---|---|---|
| D1 | 합성 통제 Byte-IoU ≥ 0.50 | 아는 답도 못 찾음 → 나머지 무의미 |
| D2 | ΔNLL_B가 무작위 대조군보다 유의하게 큼 | 모델 A의 특이성일 뿐 |
| D3 | ΔNLL_text가 무작위 대조군보다 유의하게 큼 | 이미지화의 인공물 |
| D4 | 채움값 3종 순위 Kendall τ ≥ 0.6 | 오클루전 아티팩트에 지배됨 |
| D5 | Evidence Recall@(1/16) ≥ 0.70 | 라우팅이 전수 탐색을 대체 못 함 |
| D6 | UA가 bilinear 대비 +3.0%p | UA 항 폐기 |

**D1–D3이 논문 성립 조건이다.** D6은 실패가 예상되며(경계 인식 업샘플링은 이미 실측에서 bilinear에 졌다), 실패해도 논문은 성립한다 — 제목에서 UA를 뺀다.

D6은 CPU 전용 환경에서 **미측정**으로 보고된다. 공개 UA 구현이 `.cuda()` 하드코딩에 최적화 스텝 5,100회(논문 본문은 50회)라 CPU에서 돌릴 수 없다. 코드는 다른 방법으로 슬쩍 대체하는 대신 **예외를 던진다** — UA라고 적힌 숫자는 UA에서 나와야 한다.

## 6. 스모크

데이터셋도 checkpoint도 GPU도 없이 프로토콜 전체를 확인한다.

```bash
python -m ua_sahi_mal.evidence smoke --out /tmp/smoke
```

판정 규칙을 아는 stub 분류기에 구간을 심고, 탐색이 그것을 되찾는지, 무작위 대조군을 이기는지, 예산이 순전파를 줄이는지 확인한다. `scripts/verify_env.sh`의 6단계가 이것이며, 실패하면 환경 검증 전체가 실패한다.

## 7. 연산 예산 (실측 기준)

| 항목 | 비용 |
|---|---|
| `.bytes` 파싱 | 1.2 MB 덤프당 0.11 초 |
| 코퍼스 구축 (1,636 검체) | 약 25 분 |
| 전수 오클루전 | 검체당 블록 수 순전파 (평균 1.4 MB → 342회) |
| 예산 라우팅 B=1/16 | 검체당 약 64회 + 타일 라우팅 |

전수 탐색이 감당 가능한 이유는 타일 임베딩 캐시 하나다. 이것이 없으면 매 프로브가 검체 전체를 다시 통과해야 한다.
