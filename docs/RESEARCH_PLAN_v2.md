## 0. 왜 v1 을 버리는가

v1 은 "이미지화된 코드에서 악성코드의 **위치**를 판별한다"를 목표로 삼았다. 두 번의 실패를 거쳐
이 목표가 **문제 설정 자체가 잘못되어 있었음**이 드러났다.

**첫 번째 실패 — 정답이 없다.** Malimg, BIG2015, MaleVis, MOTIF 등 공개 벤치마크는 전부 파일
단위 라벨만 제공한다. 경계 상자는 어디에도 없다. v1 은 이를 합성 데이터와 PE 섹션 구조로
우회하려 했으나, 전자는 이음매를 학습할 위험이 있고 후자는 "악성"이 아니라 "구조"의 라벨이다.

**두 번째 실패 — 문제가 애초에 성립하지 않는다.** BIG2015 검체 대부분은 파일 전체가 악성이다.
전부 악성인 파일에서 "악성 영역의 위치"는 정의되지 않는다. v1 은 이 점을 직시하지 않았다.

**세 번째 — 부품 하나가 실측에서 탈락했다.** 실제 바이트 이미지에서 경계 인식 업샘플링은
단순 bilinear 를 이기지 못했고, 바이트 값 가이드는 오차를 5.0배로 키웠다. 원인은 바이트
이미지의 영역 경계가 값 차이가 아니라 분포 변화이기 때문이다(경계 전후 Cohen's d: 바이트 값
0.96, 행 엔트로피 8.50). 상세는 `docs/results/big2015/`.

v2 는 목표를 버리지 않고 **질문을 옳게 다시 놓는다.**

## 1. 문제 재정의

> **v1**: 이 파일의 어느 바이트 구간이 악성인가? → 전부 악성인 파일에서 정의되지 않음
>
> **v2**: 이 파일의 어느 바이트 구간이 **계열 판정의 근거**인가? → 인과적으로 정의되고 검증 가능

근거 구간(evidence region)은 다음을 만족하는 바이트 구간 R 이다.

- **필요성(necessity)**: R 을 가리면 분류기가 정답 계열을 더 이상 지목하지 못한다.
- **충분성(sufficiency)**: R 만 남기고 나머지를 가려도 정답 계열을 지목한다.

이 정의는 사람의 주석을 요구하지 않는다. 마스킹 후 재추론이라는 **연산으로 검증**된다.
Petsiuk 등[1]의 deletion/insertion 지표를 바이트 구간 도메인으로 옮긴 형태다.

### 왜 이것이 실무적으로 의미 있는가

| 활용 | 근거 구간이 답하는 것 |
|---|---|
| 리버싱 우선순위 | 수 MB 바이너리에서 분석가가 먼저 열어볼 오프셋 |
| 탐지 근거 제시 | "악성입니다" → "0x1A400–0x1C800 이 이 계열의 판정 근거" |
| 시그니처 후보 도출 | 계열 전체에서 반복 지목되는 구간 = 시그니처 후보 |
| 회피 내성 진단 | 근거가 한 구간에 몰려 있으면 그 구간만 바꿔 회피 가능 |

## 2. 순환 평가를 깨는 방법 — 이 설계의 급소

**위험**: 분류기 C 의 마스킹 반응으로 정답을 만들고, 그 정답으로 검출기를 학습·평가하면,
검출기는 "C 의 saliency 를 흉내내는 법"을 배우고 평가는 그 흉내를 채점한다. AP 는 높게
나오지만 **데이터에 대해 아무것도 말하지 않는다.** 저장소 README 가 Grad-CAM pseudo-label 에
대해 이미 경고한 바로 그 함정이다.

네 겹으로 방어한다. **1~2 는 필수, 3~4 는 보강이다.**

### 방어 1 — 교차 모델 필요성 (핵심)

구간 R 을 분류기 **A** 로 발견하되, 필요성은 **독립적으로 학습된 분류기 B** 에서 검증한다.
B 는 A 와 구조·seed·표현이 모두 다르다(예: A = 바이트 이미지 CNN, B = 다른 구조/다른 seed).

> **주 지표는 A 가 아니라 B 에서 측정한 확률 하락이다.**

한 모델에만 필요한 구간은 그 모델의 특이성이고, 여러 독립 모델에 공통으로 필요한 구간은
데이터의 성질이다. 이 구분이 순환을 끊는다.

### 방어 2 — 교차 표현 필요성

R 은 바이트 구간으로 정의된다. 따라서 **이미지를 전혀 보지 않는 모델**에도 그대로 적용할 수
있다. 바이트 n-gram 또는 opcode 빈도 기반 분류기 C_text 에서 같은 바이트 구간을 가렸을 때
예측이 무너지면, R 은 이미지 표현의 산물이 아니라 **파일이 담고 있는 정보**다.

이것이 가장 강한 논증이며, "이미지화가 인공물을 만든 것 아니냐"는 리뷰어의 첫 질문에 답한다.

### 방어 3 — 합성 양성 대조 (프로토콜 교정)

정답을 아는 통제 집합을 따로 만든다. 정상 계열 검체의 바이트 이미지에 다른 계열의 구간을
알려진 위치에 합성하고, 프로토콜이 그 구간을 되찾는지 측정한다. 이것으로 프로토콜의
**민감도와 특이도를 교정**한 뒤 실제 데이터에 적용한다.

동일 기하(같은 삽입 위치·같은 길이)의 **정상→정상 하드 네거티브**를 1:1 로 포함한다.
이것이 없으면 검출기가 "악성"이 아니라 "이음매"를 학습한다. 이음매 엔트로피 차가 0.3 bit 를
넘으면 donor 를 재선택한다(코드에서 예외로 강제).

> 이 통제 집합은 **이미지 도메인에서만** 만든다. 실행 가능한 파일을 생성하지 않는다.
> 입력은 BIG2015 의 `.bytes`(배포 시점에 실행 불가하게 가공됨)를 쓴다.

### 방어 4 — 구조적 정합 (해석용, 정답 아님)

발견된 구간이 PE 구조(섹션, import 테이블, 문자열 영역, entry point)와 어떻게 겹치는지
보고한다. 정답으로 쓰지 않는다. 다만 근거가 특정 구조에 몰린다면 해석 가능한 서술이 된다.

## 3. 오클루전 아티팩트 통제

마스킹은 바이트 통계를 바꾼다. 분류기가 **제거된 정보**가 아니라 **마스킹 흔적**에 반응하면
측정 전체가 무효다. 실제 검체 2개에서 채움값 후보의 4KB 블록 엔트로피를 측정했다.

| 채움값 | 엔트로피 | 검체 1 (실제 분포 6.05, 5~95% [0.81, 6.73]) | 검체 2 (실제 4.31, [0.00, 4.94]) |
|---|---|---|---|
| `0x00` | 0.00 | **분포 밖** | 분포 안 |
| `0xCC` (int3 패딩) | 0.00 | **분포 밖** | 분포 안 |
| 균일 난수 | 7.95 | **분포 밖** | **분포 밖** |
| **히스토그램 정합** | 6.15 / 3.68 | 분포 안 | 분포 안 |

**결정**: 주 채움값은 **해당 검체의 전역 바이트 히스토그램에서 표집한 값**으로 한다. 상수
채움과 균일 난수는 강건성 확인용으로만 쓰고, 세 채움값에서 결론이 일치할 때에만 주장한다.

**필수 대조군**: 같은 크기·같은 모양의 **무작위 위치 구간**을 가린 조건. 후보 구간의 효과가
무작위 대조군보다 유의하게 커야 한다. 이것이 없으면 "무엇을 가리든 성능은 떨어진다"와
구분되지 않는다.

## 4. UA-SAHI 가 들어가는 지점

여기서 비로소 라우팅이 **실제 문제**가 된다.

4 MB 검체를 폭 512 로 래스터화하면 8,192 행이다. 8 행(4,096 B) 블록 단위로 근거를 찾으면
후보가 **1,024 개**이고, 전수 오클루전은 검체당 분류기 순전파 1,024 회다. 코퍼스 전체로는
10,868 × 1,024 ≈ 1,113 만 회.

| 방식 | 검체당 순전파 | 코퍼스 전체 (1.4 ms/회 기준) |
|---|---|---|
| 전수 오클루전 | 1,024 | 약 4.3 시간 |
| 예산 라우팅 B=1/16 (K=64) | 64 | **약 16 분** |

즉 SAHI 의 예산 제한 라우팅이 "있으면 좋은 것"이 아니라 **이 문제를 실행 가능하게 만드는
필수 요소**다. 평가 지표도 자연스럽게 정해진다 — **Evidence Recall@Budget**: 전수 탐색이
찾아낸 근거 질량 중 예산 K 로 몇 %를 회수하는가.

### UA 는 가정이 아니라 검증 대상이다

v1 은 UA 를 전제로 깔았다. v2 는 그러지 않는다. 앞선 실측에서 경계 인식 업샘플링은 바이트
이미지에서 bilinear 를 이기지 못했다. 따라서 UA 는 **절제 실험의 한 항**으로만 들어간다.

- 라우팅 점수 지도의 업샘플러: nearest / bilinear / 고정 JBU / **UA**
- 가이드 채널: G1(바이트 값) / **G3(바이트 값 + 행 엔트로피 + 빈도 순위)**
- 사전 예측: G1 은 실패한다. G3 는 개선되지만 bilinear 를 넘지 못할 가능성이 높다.
  **이 예측이 틀리는 것도 결과다.**

UA 를 실제로 측정하려면 GPU 가 필요하다. 공개 구현은 `.cuda()` 하드코딩이고 최적화 스텝이
5,100 회로 설정되어 있다(논문 본문은 50 회). 이 불일치도 보고 대상이다.

## 5. 지표

### 주 지표

| 지표 | 정의 | 무엇을 답하는가 |
|---|---|---|
| **ΔNLL_B** | 구간 마스킹 시 **모델 B** 의 정답 계열 음의 로그우도 증가 | 교차 모델 필요성 (방어 1) |
| **ΔNLL_text** | 같은 구간을 가린 비이미지 모델의 NLL 증가 | 교차 표현 필요성 (방어 2) |
| **Evidence Recall@B** | 예산 B 로 회수한 근거 질량 / 전수 탐색 근거 질량 | 라우팅 효율 |
| **Byte-IoU (합성)** | 합성 통제 집합에서 발견 구간과 주입 구간의 1-D IoU | 프로토콜 교정 (방어 3) |

### 보조 지표

- 무작위 위치 대조군 대비 효과 크기(Cohen's d)와 95% 신뢰구간
- 채움값 3종 간 순위 상관(Kendall τ) — 아티팩트 강건성
- 근거 구간의 PE 구조 분포 (방어 4)
- 검체당 분류기 순전파 횟수, 종단간 latency, peak VRAM

### 통계

계열별 층화, 3 seed, 검체 단위 paired bootstrap 1,000 회로 95% CI. 단일 실행 수치는
보고하지 않는다. 신뢰구간의 t 계수는 정확값 4.302653 을 쓴다(기존 집계 구현은 반올림값
4.3030 을 썼다 — v2 에서는 정확값으로 통일한다).

## 6. 사전등록 판정 기준

주 판정점: 블록 4,096 B, 예산 B = 1/16 (K = 64)

| # | 조건 | 미달 시 의미 |
|---|---|---|
| **D1** | 합성 통제에서 Byte-IoU ≥ 0.50 | 프로토콜이 아는 답조차 못 찾음 → 나머지 무의미 |
| **D2** | 실제 데이터에서 ΔNLL_B 가 무작위 대조군보다 유의하게 큼 (95% CI 가 0 제외) | 근거 구간이 모델 A 의 특이성일 뿐 |
| **D3** | ΔNLL_text 가 무작위 대조군보다 유의하게 큼 | 이미지화의 인공물 |
| **D4** | 채움값 3종에서 구간 순위 Kendall τ ≥ 0.6 | 오클루전 아티팩트에 지배됨 |
| **D5** | Evidence Recall@(B=1/16) ≥ 0.70 | 라우팅이 전수 탐색을 대체하지 못함 |
| **D6** | UA 가 bilinear 대비 Evidence Recall +3.0%p 이상 | UA 항 폐기, SAHI 라우팅만 유지 |

**D1–D3 이 논문의 성립 조건이다.** D4 는 방법의 신뢰성, D5 는 실용성, D6 은 UA 부품의
존치 여부를 가른다. **D6 실패는 예상되는 결과이며, 실패해도 논문은 성립한다** — 그 경우
제목에서 UA 를 빼고 "예산 제한 오클루전 탐색"으로 좁힌다.

미달 조건은 그대로 보고한다. 사후에 임계를 조정하지 않는다.

## 7. 실행 계획

| 단계 | 내용 | 산출 | 선행 조건 |
|---|---|---|---|
| **P0** | 디스크 확보, `train.7z` 추출 → 바이트 이미지로 변환 후 원본 삭제 | 검체 N 개의 이미지 저장소 | **디스크 50 GB** |
| P1 | 분류기 A·B·C_text 학습 (계열 9 클래스, 층화 분할, 해시 중복 제거) | 3 개 checkpoint | P0 |
| P2 | 합성 통제 집합 구축 + D1 교정 | 민감도·특이도 곡선 | P1 |
| P3 | 전수 오클루전 (부분집합) → 근거 질량 기준선 | Evidence Recall 의 분모 | P1 |
| P4 | 예산 라우팅 + 업샘플러 절제 → D5·D6 | 표·그림 | P3 |
| P5 | 교차 모델·교차 표현 검증 → D2·D3·D4 | 주 결과 | P3 |
| P6 | 논문 작성 | 투고본 | P5 |

### 자원 현황과 유일한 병목

| 항목 | 현황 | 판정 |
|---|---|---|
| 연산 | CPU. 소형 CNN 기준 예산 라우팅 전체 코퍼스 약 16 분 | **충분** |
| GPU | 없음 | UA 측정(D6)만 불가. 나머지는 진행 가능 |
| 데이터 | `malware-classification.zip` 35.3 GB 확보 | 있음 |
| **디스크** | **여유 17 GB. `train.7z` 만 18.8 GB** | **차단** |

검산한 수치는 다음과 같다(검체 평균 바이너리 1.4 MB, 10,868 검체 기준).

| 대상 | 총량 | v2 에 필요한가 |
|---|---|---|
| `.asm` (검체당 12~38 MB) | 약 **217 GB** | **불필요.** 마스킹에 디스어셈블리가 필요 없다 |
| `.bytes` (16진 텍스트, 바이너리의 약 3배) | 약 **45 GB** | 필요하지만 즉시 변환 후 삭제 |
| 변환 결과(폭 512 무손실 PNG) | 약 **6 GB** | 최종 보관 |
| `train.7z` 자체 | **18.8 GB** | 변환 동안만 |

따라서 `.asm` 을 쓰지 않고 `.bytes` 만 배치 단위로 추출 → 이미지 변환 → 원본 삭제를 반복하면
**최대 동시 점유는 약 25 GB**(7z 18.8 + 작업분 + 누적 이미지)다. 여유 있게 **50 GB** 를 권한다.
현재 여유 17 GB 로는 `train.7z` 를 materialize 하는 첫 단계조차 불가능하다.

**대안 두 가지.**

1. **외장 드라이브** — 가장 확실하다. 50 GB 만 있으면 전체 코퍼스를 쓸 수 있다.
2. **계열 층화 부분집합** — 예를 들어 계열당 200 검체(가장 작은 계열은 42 개 전부)로
   약 1,600 검체를 만들면 이미지 저장량이 1 GB 미만이다. 검체 2 개와는 비교할 수 없고 첫
   논문으로 방어 가능하다. 다만 `train.7z` 를 materialize 하는 문제는 그대로 남으므로,
   이 경우에도 최소 20 GB 는 확보해야 한다.

## 9. 기여 주장과 그 전에 확인할 것

### 주장하려는 것

1. 악성코드 바이트 이미지에서 **근거 구간을 인과적으로 정의하고 교차 모델·교차 표현으로
   검증하는 프로토콜**. 사람 주석 없이 정답을 구성한다.
2. 그 탐색을 **예산 제한 문제로 정식화**하고 라우팅으로 전수 탐색의 성능을 회수함을 보인다.
3. 자연 영상용 경계 인식 업샘플링이 바이트 이미지에서 왜 실패하는지에 대한 **메커니즘적 설명과
   실측**(값이 아니라 분포가 경계를 만든다).

### 주장하기 전에 반드시 확인할 것

이 세션에서는 웹 검색 프록시가 차단되어 광범위 문헌 탐색을 하지 못했다. **P0 이전에**
Google Scholar / IEEE Xplore / DBLP 에서 다음을 확인해야 한다. 이미 있다면 기여 주장을
그만큼 줄여야 한다.

- `malware occlusion explanation byte`
- `malware image saliency localization evaluation`
- `deletion insertion metric malware`
- `byte-level evidence attribution malware classifier`
- `MalConv attribution region`
- Grad-CAM 계열을 악성코드 이미지에 적용한 연구가 **인과적 검증까지** 했는지

특히 3 번 주장은 UA 논문[2]과 JBU[3] 의 범위 밖이라 비교적 안전하지만, 1·2 번은
설명가능성(XAI) 문헌과 겹칠 여지가 크다.
